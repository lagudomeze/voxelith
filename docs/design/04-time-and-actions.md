# 时间与行动

这一篇只讲**模型**：时间什么时候走、一次行动由哪些部分组成、它们之间什么关系。
引擎怎么实现（用 Bevy 的哪个时钟、几步一秒）见 [`bevy/03-time-and-actions.md`](bevy/03-time-and-actions.md)。

上游需求：`GP-03`…`GP-11`、`GP-25`…`GP-32`、`GP-34`…`GP-38`、`SY-40`…`SY-43`、`SY-57`。

---

## 一、时间什么时候走

> **世界只在"玩家已经决策、正在结算"的过程中流动。**

这句话是从需求拼出来的，它一个人解释了需求里所有关于时间的说法：

| 需求 | 由这句话得到 |
| --- | --- |
| 玩家不操作时时间冻结，玩家一操作怪物才动 | 你没有在飞的前摇 → 停 ✓ |
| `GP-30` 怪物在流动的时间里决定与出手 | 你的前摇在飞 → 时间在走 → 怪物同时行动 ✓ |
| `GP-32` 有人在威胁你 → 暂停 | 有指向你的行动 → 停（哪怕你正在前摇 ✓）✓ |
| `SY-57` 站着不动时中毒不掉血 | 你没在做事 → 停 → 状态时长、每跳、耐久恢复全停 ✓ |

**推论（重要）**：你站着不动时，**两只怪物之间的战斗也不会推进** ✓ —— 因为时间冻结是全局的 ✓ 世界为你停下 ✓

**时间轴只有一条**，所有角色共用 ✓ 每个角色身上只放"我下次行动在哪个绝对时刻"，不各自计时。

冻结有三个触发，任何一个成立就停（可以同时成立）：

| 触发 | 含义 | 来源 |
| --- | --- | --- |
| `waiting_for_player` | 玩家没有在飞的前摇 → 该你做决定了 | 一句话需求 |
| `threat` | 有指着玩家、还没生效的行动悬着 | `GP-32` |
| `manual` | 玩家自己按的暂停（看盘用；**可以下指令**，代价照付） | 用户确认 |

## 二、一次行动的一生

```
Skill（技能：静态定义）
   │  begin_action ← 生成过程：受各种因素影响（属性、状态、工具、方块…）
   │    ① 校验参数形状  ② 先删旧行动  ③ 扣代价  ④ 算前摇、算威胁
   ▼
Action（行动实体：一次算定，生成后不再变）
   │  前摇：从生成到生效的那段游戏时间
   │  到点（resolves_at）
   ▼
Effect（效果：执行，不可撤回）
   └─► 产物实体（火球 → 飞行 → 命中/到点 → 范围爆炸）
```

需求里写死的次序（`GP-26`）：**释放 → 扣掉代价（资源与冷却）→ 出现那一次行动 → 走前摇 → 到点执行效果** ✓
**代价在行动出现之前就扣掉**，所以取消也不退 ✓（`SY-43`）

## 三、名词表

| 术语 | 代码 | 是什么 | 谁定义 / 何时定 |
| --- | --- | --- | --- |
| **技能** | `SkillId` | 静态定义：基础前摇、代价、参数形状、效果列表 | 内容；先写死在代码 |
| **释放** | `begin_action` | 决策 → 校验 → 扣代价 → 生成行动实体 | 唯一入口 |
| **行动** | `Action` | **"那一次行动"**（`GP-25`/`GP-27` 针对的就是它） | 生成时一次算定 |
| **前摇** | `Action.resolves_at` | 行动从生成到生效的那段时间；**不是独立实体**，是行动的属性 | 生成时算定 |
| **生效 / 结算** | 到点执行 | 到点执行效果，不可撤回（`GP-06` 第二段） | 到点时 |
| **效果** | `SkillId` 里定义 | 生效时做什么（下一块设计） | 内容 |
| **产物** | 火球实体之类 | 效果生成的东西，有自己的生命 | 生效时 |
| **打断 / 取消** | 删掉 `Action` | 生效前删掉它——**同一个操作**，只是来源不同 | 仅生效前 |
| **代价** | `Cost` | 资源 + 冷却；**在生成行动之前就扣**，不退 | 释放时 |
| **强度** | `Potency` | 对抗时比大小的值（`SY-41`）；**是可修正的量** | 释放时给基准，之后可被修正 |
| **威胁** | `Threatens` / `Threats` | 生成时算好的"这次行动影响到谁" | 生成时算一次 |

## 四、三条不变量

1. **`Action` 生成后不变**：`resolves_at`、`skill`、`params` 谁都不许改 ✓ 只由 `begin_action` 写一次 ✓
   （"生成过程受各种因素影响，生成后定下来"）
2. **只有 `Potency` 会变**：它是可修正的量 ✓ "削弱敌人在飞的这次行动" = 给行动实体挂 `Modifier<Potency>` ✓ 对抗里读到的就是 `SY-41` 说的"**此刻**的强度" ✓
3. **生效前可删（打断 / 取消 / 放弃），生效后不可撤回** ✓（`GP-06`）
   **前摇中途被改变**（施法变慢、被击晕而延长）**不支持** ✓ —— 要支持就得把前摇从"绝对时刻"改成"进度/速度"型 ✗ 结构完全不同 ✓ 打断已经够用 ✓

## 五、打断、取消、放弃：同一个操作

| 来源 | 触发 | 需求 |
| --- | --- | --- |
| 自己取消 | 落任何新技能（一次只做一件事 `GP-03`）、移动取消当前施法（`GP-04`） | `GP-04` |
| 敌人反制 | 落一个带打断能力的技能 → 再由对抗决定（`SY-41`） | `GP-08`、`GP-29` |
| 自己放弃 | 威胁暂停窗口里做别的动作 | `GP-09` |

机制上都只是**删掉那个行动实体** ✓ 区别只在来源与判定 ✓
打断成功 = 那一次行动被删除，**敌人本人还在**，下一拍可以重新决定 ✓（`GP-29`）
被打断/取消时**没有部分效果**：前摇一过就等于生效，不存在"做了一半" ✓
（挖掘是例外：它把过程本身做成了效果，见下一块）

## 六、威胁

**威胁不是独立机制，是行动的一个视图**：生成行动时算一次"这次行动会影响到谁" ✓ 存成关系（`Threatens` / `Threats`）✓

- 可以同时有多个威胁悬着 ✓ 世界停在这里等你处理 ✓ 先处理哪个由玩家定 ✓（`GP-28`）
- 世界因"有人在威胁你"而暂停 ✓ 没人威胁你时不因此暂停 ✓（`GP-32`）
- 反制窗口是"等你决定"的暂停 ✓ 不做反制而做别的就是放弃 ✓（`GP-09`）

**可见性**（支柱 2："威胁看得见，就能抢先"；"看不见就只能承受"）取决于**效果的影响范围**，属于下一块（效果与技能）✓

## 七、代价：同步事务、拒绝而非夹取

代价在行动出现**之前**就扣（`GP-26`）✓ 而"够不够"必须**当场**知道 —— 否则同一帧里两条请求会双双通过检查、把资源扣成负数 ✗

所以改值分成两条路，判据只有一句：**要不要当场知道结果**。

| | 走哪条 | 为什么 |
| --- | --- | --- |
| **代价**（`Cost<Q>`：一种量一个组件）| **同步事务**：读 → 查 → 扣，全在一个系统里 | 必须当场知道够不够 ✓ |
| 伤害 / 治疗 / 持续每跳 | **消息**（`Adjust` → 落地系统）| 总会发生 ✓ 不需要当场结果 ✓ 还要留给别人插手的余地 |

三条规则：

1. **全部或全不**：多条代价里有一条付不起 → **一条都不扣** ✓（跨资源也一样 ✓）
2. **拒绝而非夹取**：不够就是"这次放不出来" ✓ 发一条拒绝消息给 UI / 音效 ✓
   夹到 0 仍释放 ✗ 允许负数 ✗
3. **编程错误与游戏内失败分开**：参数形状不对、引用了没有的技能模板 → panic ✓；
   资源不够、冷却中 → 拒绝 ✓（游戏内正常情况 ✗ 不该炸）

扣减本身走 core 的**唯一通路**（`voxelith_core::change`，带实体）✓ 于是留痕（`SY-05`）与夹取将来只加在一处 ✓

## 八、边界

- **效果与技能**（效果列表长什么样、对抗与结果怎么拆、影响范围、冷却计时）是**下一块** ✓
- 这一块只做到：**时钟 + 行动实体 + `begin_action` + 到点发一条 `ResolveAction`** ✓
  效果怎么处理先留空壳 ✓ 这样效果那块怎么设计都不会反过来逼这一块改结构 ✓
