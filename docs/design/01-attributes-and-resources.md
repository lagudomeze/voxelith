# 属性与资源

这一篇定**可修正的量（属性与资源）**的模型，与引擎无关。数值公式的具体取值属数值阶段；Bevy 侧的写法见 [bevy/](bevy/README.md)。

组件形状的跨主题前提见 [组件约定](00-component-conventions.md)。

**上游需求**：`SY-01`…`SY-08`、`SY-30`…`SY-34`、`SY-53`、`SY-56`、`SY-58`、`SY-59`、`GP-24`、`GP-39`、`GP-44`

## 一、可修正的量：一个标记 + 两种载体

**每个"可修正的量"有一个标记**——只是它的名字（"力量""血量上限"……）。**修正指向的是标记，不是组件。**

量只有两种形状：

| 形状 | 内容 | 例子 |
| --- | --- | --- |
| **单值型** | 一个基础值 | 力量、敏捷、护甲、移动速度、挖掘力 |
| **资源型** | 一个当前值 + 一个基础上限 | 血量、精力、法力、悖论 |

- **单值型**：读出来的就是"基础值 + 修正"。
- **资源型**：**只有当前值是状态**（由事件改，不走修正）；**上限与单值型共用同一套修正**——所以"这件装备 +20 血量上限"与"+5 力量"是同一种东西。
- 好处：十几项属性、若干条资源，共用两种形状和**一条读取路径**，而不是各写一个组件、各抄一遍算法。**加一个新量＝加一个标记 + 一行别名。**

## 二、修正

一个修正 = **一个实体**，带一份修正，并通过关系指向被修正的角色。装上一件装备就生成、卸下就销毁（`SY-33` 因此不需要专门写代码）。

| 修正 | 含义 |
| --- | --- |
| **平加** | 绝对值（`+5 力量`） |
| **比例** | **按基础值**的比例（`+50% 基础力量`）——不是按"已经加过别的修正之后的值" |

**两条来源**：

- **外部来源**（装备、增益、减益）：各自有生命周期；
- **派生来源**（主导属性对派生量的影响，如"体质 → 血量上限"）：由 system 维护，属性变化时更新对应的修正。

## 三、读出：收集与公式分两步

1. **收集**：把指向某个标记的所有修正归约成一个总和（**平加和**、**比例和**）。只读、不做计算。
2. **公式**：`最终值 = 基础值 + 平加和 + 基础值 × 比例和`。这是一个**纯函数**——不带世界、不遍历，可以单独测。

**为什么分两步**：公式能被单测；收集那一层将来要并行、要换策略，都不会动到公式。

**这条式子的三条性质**（都是选它的理由）：

| 性质 | 为什么成立 |
| --- | --- |
| **顺序无关** | 全是加法归约，修正的登记顺序不影响结果 |
| **可并行** | 每个修正只依赖"基础值 + 它自己"，彼此不依赖 |
| **不会指数增长** | 不做"比例乘比例"（`Π(1+r)`：堆十个 +50% 就是 1.5¹⁰ ≈ 58 倍） |

**明确不做**：覆盖（"直接设为 20"）与任何依赖顺序的修正。修正层只管加成；**下限、曲线这类"读出来之后再处理"的规则，属于用它的 system**。

**连带改了需求**：本设计让 `SY-08` 的"减速收益递减"失效（加法叠加下减速是线性的，相对效应反而递增），已把该条改成只要求"**速度恒为正**"（2026-10-09）。

**一条护栏（与 `SY-16` 同理，只是反着来）**：**"减少型"的比例必须有下限**。减速、减消耗、减冷却这类，纯加法叠加能一路堆到 0 甚至负数，而"0 冷却 / 0 消耗"会让机制直接失效。所以这类量的比例和要有下界（具体值属数值阶段）。

## 四、资源的具体规则

- **上限降低时**（卸下加血量的装备、中了减上限的效果）：当前值夹到新上限，**夹取绝不致死**（至少保留 1 点）。
- **资源可以为负**，负值意味着什么由**各自的 system** 决定：血量 ≤ 0 由死亡 system 判定（`GP-24`），精力为负由释放与冲刺的 system 自己检查。组件层不设下限。
- **变动规则是一组独立组件**：每秒回复、不回复、动态衰减、挨打才涨、越高越糟、绝对上限……资源不是"一种东西"，而是"**一个数值 + 一串规则**"（`SY-06`）。将来加"悖论法师""自然守护者"这类角色，是**换一组规则**，不是加代码。
- **每次变动都留痕**：任何一次资源变化都产生一条记录——**从多少、到多少、因为什么**。战斗日志直接读它（`SY-05`）；"治疗与扣血走同一条通路"（`SY-17`）自然成立；将来"改写这次变动"的效果挂在这条通路上。
