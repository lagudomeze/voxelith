# 属性与资源

这一篇定**六维属性、修正、血量与精力**的模型，与引擎无关。数值公式的具体取值属数值阶段；Bevy 侧的写法见 [bevy/](bevy/README.md)。

组件形状的跨主题前提见 [组件约定](00-component-conventions.md)。

**上游需求**：`SY-01`…`SY-08`、`SY-30`…`SY-34`、`SY-53`、`SY-56`、`SY-58`、`SY-59`、`GP-24`、`GP-39`、`GP-44`

## 一、属性：六项各自一个组件

| 组件 | 内容 |
| --- | --- |
| `Strength` / `Dexterity` / `Constitution` / `Perception` / `Magic` / `Willpower` | 每项一个独立组件，值是实数 |

- 里面存的是**基础值**：加点、永久强化改的就是它。
- 六项各自独立、不合成一个结构体，理由有三：**单独挂载**（"只有力量、没有别的属性"的东西不必硬凑六项）、**单独读取**、**单独覆盖**；组合时一行一项。
- 六项属性是**引擎能力**（加第七项要改代码），它们本身不带规则——"力量影响什么"写在用到它的 system 里（`SY-32`、`SY-53`、`SY-56`）。

## 二、修正：独立实体 + 指回主人的关系

一个修正 = **一个实体**，带一份加值，并通过**关系**指向被修正的角色。

- **装上一件 +5 力量的装备** → 生成这样一个实体；
- **卸下** → 销毁它 → 修正立刻消失。`SY-33`（"移除后立刻失效"）因此不需要专门写代码；
- 一个来源影响多项 → 一个实体带多份加值，或生成多个实体，两种都可以；
- 修正有**两种**：平加与按基础值的比例（见上）。
- 修正有**两个来源**：
  - **外部来源**（装备、增益、减益）：各自有生命周期——装上就生成、卸下就销毁；
  - **派生来源**（主导属性对派生量的影响，如"体质 → 血量上限"）：由 system 维护，属性变化时更新对应的修正。

**读出规则（一条式子，两种情况）：**

```
最终值 = 基础值 + Σ平加 + 基础值 × Σ比例
```

- **平加**（`+5 力量`）：绝对值，与基础值无关。
- **比例**（`+50% 基础值`）：**基于基础值**，不是基于"已经加过别的修正之后的值"。
- **每次读时算，不缓存**：修正数量是个位数，遍历很便宜；缓存会引入"忘了重算"这一类隐蔽错误。
- 这是**唯一**的值（`SY-58`）：没有"显示值 / 有效值"两套。

**为什么是这条式子**——三条性质都是选它的理由：

| 性质 | 为什么成立 |
| --- | --- |
| **顺序无关** | 全部是加法归约，修正的存放顺序不影响结果 |
| **可并行** | 每个修正只依赖"基础值 + 它自己"，彼此不依赖，可以各算一份再归约 |
| **不会指数增长** | 不做"比例乘比例"（`Π(1+r)`：堆十个 +50% 就是 1.5¹⁰ ≈ 58 倍），叠加是线性的 |

**明确不做**：覆盖（"直接设为 20"）与任何依赖顺序的修正——它们正是破坏交换律的那一类。修正层只管加成；**下限、曲线这类"读出来之后再处理"的规则，属于用它的 system**。

**一条护栏（与 `SY-16` 同理，只是反着来）**：**"减少型"的比例必须有下限**。减速、减消耗、减冷却这类，纯加法叠加能一路堆到 0 甚至负数，而"0 冷却 / 0 消耗"会让机制直接失效。所以这类量的 Σ比例 要有下界（具体值属数值阶段）。

## 三、资源：当前值 + 一串规则

### 状态只有当前值

| 组件 | 内容 |
| --- | --- |
| `Health` | 当前值（实数） |
| `Stamina` | 当前值（实数） |

- **资源有基础上限**：它来自内容配置，是一个确定的数。
- **对上限的调整（"这件装备 +20 血量上限"）走与属性同一套修正机制**，不另开一条路。所以 **最终上限 = 基础上限 + Σ修正**，同样**每次读时算、不缓存**。
- **主导属性也走修正**：像"体质每点 +5 血量上限"这样的关系，不是读路径里的一条公式，而是**一条由 system 维护的修正**。于是"**一切皆修正**"——读任何一个量的规则只有一条：**基础值 + Σ修正**。
- 存下来的只有**当前值**与**基础值**，不存"最终值"——这样不会出现"存了一份上限、又和体质打架"。
- **资源可以为负**，负值意味着什么由**各自的 system** 决定：血量 ≤ 0 由死亡 system 判定（`GP-24`），精力为负由释放与冲刺的 system 自己检查。组件层不设下限。
- **上限降低时**（卸下加血量的装备、中了减上限的效果）：当前值夹到新上限，**夹取绝不致死**（至少保留 1 点）。

### 变动规则是一组独立组件

资源不是"一种东西"，而是"**一个数值 + 一串规则**"。规则各自是组件，组合出不同手感（`SY-06`）：

| 规则 | 表达的效果 |
| --- | --- |
| 每秒回复 | 小幅回复 |
| 不回复 | 不回，靠打怪赚 |
| 动态衰减 | 每时每刻都在掉 |
| 挨打才涨 | 受击增长 |
| 越高越糟 | 反向资源（悖论 / 均衡这类专属资源） |
| 绝对上限 | 上限另有天花板 |

将来加"悖论法师""自然守护者"这类角色，是**换一组规则**，不是加代码。

### 每次变动都留痕

任何一次资源变化都产生一条记录：**从多少、到多少、因为什么**。

- 战斗日志直接读它（`SY-05`）；
- "治疗与扣血走同一条通路、只靠正负号区分"（`SY-17`）自然成立；
- 将来"改写这次变动"的效果（减伤、增疗）挂在这条通路上。
