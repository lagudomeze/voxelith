# 数值设计（ToME4 参考）

**定位**：技术参考，不是规则。本文回答"**数值该长成什么样**"，
以及"为什么选这条曲线而不是那条"。

参考对象是 [ToME4](https://te4.org/)（`t-engine4/`，GPL，© 2009–2019 Nicolas Casalini）。
我们**只取机制与数值设计，不抄实现**——那边是 Lua 的命令式写法，
与本项目的 Bevy ECS + `.ron` 内容驱动差别很大，代码层面没有可搬的东西。

> 注意：`t-engine4/` 只是**参考资料**，不是本项目的依赖、也不是被链接的代码。
> 它不在 Cargo workspace 里，不参与构建，守卫不扫它。

---

## 1. 为什么需要专门一层的数值原语

三条约束同时成立，逼出了现在这套设计：

1. **内容驱动**（R13）：加技能/状态不改代码 ⇒ 曲线必须能在 `.ron` 里写。
2. **受控闭集**（`combat-design.md` §3）：`Value` 的变体是引擎能力，不随内容增长
   ⇒ 不能给每个技能写一个专用函数。
3. **战斗必须可复现**：同样的输入永远同样的输出 ⇒ 曲线必须是纯函数、无隐藏状态。

所以曲线只能是**少数几个通用的、参数化的原语**，作者用参数表达设计意图。
ToME4 恰好也走到了同一个结构上（它有三个函数，两两之间只差参数），
所以我们把它收敛成**两个**原语。

## 2. 两个原语

都在 `voxelith-axiom` 的 `behaviors::value::curve` 里，都接在 `Value` 表达式树上。

| 原语 | 回答的问题 | ToME4 对应 |
|---|---|---|
| `Scale` | "技能升到 5 级该有多强？" | `combatTalentScale` / `combatTalentLimit` |
| `Rescale` | "属性堆到 300 之后还有多少用？" | `rescaleCombatStats` |

**两者不可互相替代**：`Scale` 的锚点是**设计意图**（你要多强），
`Rescale` 只做**压缩**（全局尺度），它不设定目标值。
一个技能常常两者都用：先用 `Scale` 从等级算出基础值，再用 `Rescale` 接进全局尺度。

### 2.1 `Scale`：过两个锚点拟合一条曲线

```
t(x)  = x^power        或  log10(x)        （单调变换）
m     = (high - low) / (t(anchor_high) - t(anchor_low))
结果  = m · t(x) + low - m · t(anchor_low)
```

锚点**精确**：`x = anchor_low` 处得到 `low`，`x = anchor_high` 处得到 `high`。
作者只要说清"两端各想要多少"，中间形状交给 `power`。

**锚点必须成对选**——这是移植时最容易错的一处，ToME4 自己就分了两套：

| 喂什么 | 锚点 | 理由 |
|---|---|---|
| 等级 / 技能点 | `1 .. 5`（`Anchors::TALENT`） | 天赋 1 级与 5 级 |
| 属性值 | `10 .. 100`（`Anchors::STAT`） | 属性起点 10、上限 100 |

把 `1..5` 的锚点套到属性上，曲线会几乎没有增长（属性 10→100 的变化远大于 1→5）。
所以 `AnchorsRon` 是 `.ron` 里的**显式字段**，不给"聪明"的默认值猜。

**`power` 怎么选**：

| `power` | 形状 | 什么时候用 |
|---|---|---|
| `< 1`（默认 `0.5`） | 前期涨得快、后期趋缓 | 绝大多数成长曲线的默认 |
| `= 1` | 线性 | 想让每级收益一样时 |
| `> 1` | 后期加速 | 罕见；通常配 `Limit` 用 |
| `Log` | 极早熟，前期就接近上限 | 被动/辅助类，前几点就该到位 |

**`ScalePower::Limit(limit)`**：以 `limit` 为渐近上限，**永远不会越过**。
求的是过两个锚点、以 `limit` 为渐近线的指数曲线：

```
结果 = limit + (low - limit) · exp(a · (t(x) - t(anchor_low)))
a    = ln( (high - limit) / (low - limit) ) / (t(anchor_high) - t(anchor_low))
```

**要求 `low`、`high`、`limit` 单调**，否则曲线会拐弯——这种配置会被拒绝
（返回 `None`，求值时回退 `0.0`，不 panic）。

**什么时候必须用 `Limit`**：任何**不能失控**的量。ToME4 用它管抗性上限、
冷却下限、持续时间上限、免疫率、百分比类效果。凡是"理论上可能到 100% 以上"的，
都该用 `Limit` 而不是 `Power`。

### 2.2 `Rescale`：分段线性压缩

```
有效 = min(
    x,
    20 + (x - 20) / 2,      // 20 之后：每 2 点原始值换 1 点有效值
    40 + (x - 60) / 3,      // 60 之后：每 3 点换 1 点
    60 + (x - 120) / 4,     // 120 之后：每 4 点换 1 点
    ...
)
```

## 3. 为什么是"分段线性"而不是对数

这是 ToME4 最有价值的一个判断，值得单独说。

简单线性缩放很糟：玩家看到 `+100 力量` 只变成 `+20 有效值`，会觉得加点没意义。
**取对数更糟**：低端极陡（前几点收益巨大）、高端极平（几乎无收益），
而且玩家**无法心算**——"我现在 137 力量，再多 5 点值多少"没人算得出来。

ToME4 源码里的注释把理由讲得很直白：

> the first twenty ranks cost 1 point each, the second twenty cost two each,
> and so on … much better for players than some logarithmic mess.

分段线性的每一段兑换率都是**整数比**："现在每 4 点换 1 点"是能说清楚、
能在 UI 上展示、能被玩家规划的。同时它仍然**每段都在涨**（有正反馈），
只是斜率逐段变缓（平衡可控）。

**两个好处同时拿到**：玩家看到的数字线性增长（升级有快感），
而真正进公式的数字被压平（数值不爆炸）。

### 实测换段点

`Rescale::new(x).eval(raw)` 的输出（`interval = 20`，与 ToME4 一致）：

| raw | 20 | 40 | 60 | 80 | 100 | 120 | 150 | 200 | 300 | 400 | 500 | 1000 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 有效 | 20 | 30 | 40 | 46.7 | 53.3 | 60 | 67.5 | 80 | 100 | 116.7 | 131.4 | 190 |

换段点 `20 / 60 / 120 / 200 / 300 …` 与 ToME4 完全一致（有单测守住）。

**`interval` 可配**：ToME4 给"属性总和"用了 `45` 而不是 `20`，
因为属性总和天然比力量/护甲小——用 `20` 会压得太狠。
我们的 `Rescale::with_interval` 保留了这个自由度。

**负值原样通过**：`x <= 0` 时不压缩。否则一个减益会莫名其妙变小，
玩家完全看不懂。ToME4 也只在正区间压缩。

## 4. 从 ToME4 学到的其余机制（**尚未落地**，按优先级排）

这一节是"看过了、值得抄"的清单，**代码里还没有**。每条都附上为什么值得抄、
以及它对我们这个游戏的适配程度。

### 4.1 抗性：加算上限 + 乘算合并 + 穿透只削正抗性 ⭐

ToME4 的抗性公式（`combatGetResist`）：

```
a = min(resists.all / 100, 1)
b = min(resists[type] / 100, 1)
r = clamp(100 · (1 - (1-a)(1-b)),  -100,  resists_cap.all + resists_cap[type])
```

三个设计点，每个都有明确理由：

1. **`all` 与具体类型乘算合并**（+50% 全体 与 +50% 火焰 = 75%，不是 100%）
   ⇒ 防止"堆一种增益就无敌"。
2. **上限是加算的**（默认 100 + 物品的 `{FIRE: 10}` = 110 上限）
   ⇒ 让"提高上限"成为一个**独立的、可设计的奖励维度**，而不是靠破表。
   还允许**负上限**（某件神器把光抗上限 −25）——一个很有意思的代价设计。
3. **地板是 −100%**（受到双倍伤害）⇒ 让"降抗性"是真威胁，不是摆设。

**穿透（penetration）只作用于正抗性**，且硬上限 70：

```
if res > 0: res = res * (100 - pen) / 100      // 只削正的
pen = min(pen, 70)
```

⇒ 穿透**永远不能把抗性变成易伤**。这条极其重要：否则"堆穿透"会变成
一个自我强化的无限增益。我们做抗性时必须照搬这两条（乘算合并 + 上限加算）。

### 4.2 护甲：`hardiness` 分割，而不是随机减免 ⭐

```
pres  = clamp(hardiness / 100, 0, 1)
armor = max(0, armor - apr)
dam   = max(dam·pres - armor, 0) + dam·(1 - pres)
```

**这一击被切成两半**：`hardiness` 那一半受护甲**平减**，剩下 `(1-hardiness)`
那一半**完全绕过护甲**。所以护甲能吸收的上限是 `min(dam·hardiness, armor)`。

这个设计解决了"护甲要么没用要么无敌"的老问题：

- 面对**小伤害**（快攻、多段），护甲那一半能吃掉大部分 ⇒ 护甲值钱。
- 面对**大伤害**（重击、爆发），`(1-hardiness)` 那一半直接穿过去 ⇒ 护甲不能免死。

`hardiness` 本身就是"这件护甲能挡住伤害的哪一部分"，基础 30%，
重甲训练能推到 ~59%。ToME4 里 `EFF_BREACH`（破甲）会把 hardiness **减半**——
这是个很好的"破防"机制，比单纯减护甲数值有意思。

**注意**：这个版本（1.7.x）的护甲路径**没有随机**。早期版本有
`rng.range(0, armor)`，现在改成了确定性分割。我们采用确定性的版本
（战斗要可复现，见第 1 节）。

### 4.3 判定：一条线性对抗原语贯穿全部 ⭐⭐

ToME4 用**同一个函数**做命中判定、豁免判定、击退判定：

```
hit% = clamp(ceil(50 + 2.5 · (atk - def)), min, max)
```

**每 1 点优势 = 2.5 个百分点**，对称地围绕 50%。
所以 ±20 点是"必定命中 / 必定失手"——**边界是硬的、可计算的**。

这条对我们的 `Contest` 是直接印证：我们已经有了
`Formula::Difference` / `Ratio` / `RollUnder`（`contest.rs`），
ToME4 用的正是 `Difference` 那一支。

**最值得抄的是下限与上限的用法**：

- 命中判定用 `[0, 100]`。
- **状态施加用 `[0, 95]`**——即**永远存在 5% 的概率让负面状态落地**。
- 上限 95% 而不是 100%，是为了不让"堆豁免"变成绝对免疫。

⇒ **我们做状态施加时应当默认夹在 `[5, 95]`**，而不是 `[0, 100]`。
这是一个很便宜、但很大的体验改进：玩家永远有希望，也永远不能完全躺赢。

**跨档（cross-tier）**：每 20 点算一档，
`档差 = max(0, ceil(atk/20) - ceil(def/20))`。攻击方每领先一档，
就给对方挂一个轻微的副状态（失衡/法术震荡/思维受阻）**若干回合**（= 档差）。
效果：**堆数值永远有回报**，即使主效果被豁免掉了。
这是个很聪明的"保底收益"设计。

### 4.4 状态的两层模型 ⭐⭐

ToME4 的 `on_set_temporary_effect` 同时做了**两件独立的事**：

```
1. 二元豁免骰：  P(抵抗) = clamp(50 + 2.5·(save - power), 0, 95)%
                 → 命中则状态完全不施加
2. 持续时间缩放：duration% = 1 - (save - power) / 20
                 → save = power 时满时长；领先 10 点时一半；领先 20 点时 0
```

**这是"双管齐下"，而且两层是独立的**——先掷骰决定施不施加，
再按差值决定施加多久。

设计上很强的地方：

- `save ≈ power` 时：50% 概率完全免疫，命中则满时长。
- `save` 领先 20+ 时：**几乎总是完全免疫**（95% 上限）。
- `power` 领先 20+ 时：**几乎总是满时长**（5% 下限保证攻击方不会白费）。

⇒ 数值差距被翻译成"概率 + 时长"两个维度，而不是简单的"成/不成"。
这比单一骰子有层次得多。

另外两条同样重要：

- **`min_dur`**：即使缩放到 0，也保证至少 N 回合。ToME4 在很多地方用 `min_dur = 1`
  ⇒ 强攻击力**永远能留下点什么**，不会因为运气/差值被完全吃掉。
- **刷新永不缩短**：`dur = max(新, 旧)`。防止"用一个小技能把大技能的时长顶掉"
  这种反直觉操作。

**`type = "other"` 的效果永远不参与豁免**——ToME4 用这个类别装"不该被豁免的东西"。
而**不可豁免的硬控是作者的选择**（不设 `apply_power` 就不走豁免流程）。
⇒ 我们应当显式区分"**可豁免**"与"**必然生效**"两类状态，而不是让每个技能自己决定。

### 4.5 资源：五种不同的"手感"⭐⭐

ToME4 的资源系统最值得学的**不是数值，而是模型多样性**——
它给每种资源一个**不同的经济学**，于是职业玩起来感觉完全不同：

| 模型 | 例子 | 手感 |
|---|---|---|
| 每回合小幅回（`0.25–0.5`） | 生命、耐力、法力 | "慢慢恢复"，逼你控节奏 |
| **不回，靠打怪赚** | 活力（vim）、灵魂（soul） | 资源是**战利品**，鼓励进攻 |
| **反向：越高越糟** | 均衡（equilibrium）、悖论（paradox） | 用得越多越危险，自己给自己上强度 |
| **动态衰减** | 仇恨（hate，`-0.7·(hate/100)^1.5`/回合） | 动量表，脱战就衰减 |
| **挨打才涨** | 反馈（feedback，受伤的 50%→20%） | 受苦型资源，越挨打越强 |
| **硬整数上限** | 灵魂（上限 10） | 离散的"尸体经济"，不是进度条 |

**最值得抄的两个**：

**均衡（equilibrium）——反向资源 + 平方根失败曲线**：

```
eq < WIL 时：永不失败
否则：失败率 = clamp( sqrt(eq - WIL) / 60, 0, 1 )
```

失败率随超出量**平方根增长**：超出 81 点 = 15%，900 点 = 50%，3600 点 = 100%。
⇒ **小幅超出几乎免费，大幅超出灾难性**。这是"风险自选"的绝佳范例：
玩家可以自己决定要浪到什么程度。

**悖论（paradox）——反向资源 + 六次方悬崖**：

```
modified = max(0, paradox - 2·WIL + ...)
modified <= 300 时：0% 失败
否则：失败率 = (modified / 300)^6
```

⇒ 有一个**死区**（完全安全），然后**六次方**陡增。300 → 400（+33%）时风险
从 0% 到 5%，600 时 64%。这是"舒适区 + 悬崖"的设计：
玩家有自己的"舒服的悖论水位"，越线就是赌博。

**我们该怎么用**：`Resources` 目前只有 `max` / `regen` / `start_full`。
要支持上面这些，需要加的是**模型字段**而不是新资源类型：
"反向"（成本加到池里）、"不回"、"条件回复"（击杀/受击）。
建议优先做**反向**与**击杀回复**——这两个对角色的玩法分化最大。

### 4.6 冷却与速度的分离 ⭐

ToME4 里一件很容易搞错但设计得很对的事：

```
冷却：每个"游戏回合"固定减 1（不受 haste 影响）
速度：改变"每回合获得多少能量" ⇒ 每回合能做几个动作
```

⇒ **加速让你在同样的回合数里做更多动作，但冷却和状态时长仍按回合数走。**
净效果：加速**缩短了冷却的墙钟时间**，但没有破坏"冷却 = 几个回合"的模型。

对比"加速也加速冷却"的做法：那会让 haste 变成**指数级**收益
（更多动作 → 更快冷却 → 更多动作）。ToME4 明确避开了这个陷阱。

**另一处细节**：加速与减速**不对称**：

```
if add >= 0: speed = base + add          // 加速：线性加
else:        speed = base / (1 + |add|)  // 减速：调和
```

⇒ 减速永远**不能**把速度变成 0 或负数（`base/(1+|add|)` 恒正），
且减速的边际收益递减（从 1 到 1/2 很痛，从 1/10 到 1/11 无所谓）。
这是个很稳的写法。**我们做 `TimeScale` 时应当照搬这个不对称。**

### 4.7 状态合并的两种语义

重复施加同一个状态时，ToME4 按效果类型选两种之一：

1. **伤害守恒平均**（DoT 类：流血、中毒、燃烧）：
   ```
   时长 = ceil((旧时长 + 新时长) / 2)
   强度 = (旧强度·旧时长 + 新强度·新时长) / 时长
   ```
   ⇒ **总伤害不变**，只是重新分配。避免"连点同一个技能导致 DoT 伤害指数增长"。
2. **取最强 / 取最长**（减速、潮湿等）：`强度 = max`、`时长 = max`。

⇒ 我们的状态系统需要**显式的合并策略字段**，而不是一个全局规则。
DoT 用平均、增益/减益用取最强，这是最安全的两条默认。

### 4.8 我们**明确不抄**的

诚实记录取舍，避免以后有人问"为什么没做"：

| ToME4 的做法 | 为什么不抄 |
|---|---|
| 179 种伤害类型 + 手写复合投影器 | 我们的设计是"伤害 = `Contest` 成功后改资源池"（R10），**没有 `Damage` 变体**。伤害类型通过资源的 ID 表达即可，不需要类型树 |
| `x^1.04` 超线性伤害放大 | ToME4 加它是为了补偿被 `rescaleCombatStats` 压扁的力量值。我们只要**别把力量压那么狠**，就不需要这个补偿。多一项隐式放大就多一个失控点 |
| 命中判定带 `factor` 参数但从不使用 | 死参数。ToME4 里还有若干处传了这个参数并**以为**它有效（实际无效）。我们不留这种坑，参数要么生效要么不存在 |
| 经验曲线（`load.lua`） | 它的 `m_k` 衰减分支判断的是**目标等级**而不是循环下标，导致 30 级有一个 6 倍的突兀跳变（249 → 1467 → 380）。这是 bug 不是设计。我们的等级/经验曲线要单独设计 |
| 随机词缀的 `mbonus` 正态分布 | 需要随机数参与"生成"，与"战斗可复现"不冲突，但优先级低。等有掉落系统再说 |
| `resists_actor_type`（按攻击者种族抗性） | 概念本身有用（"对亡灵额外伤害"），但 ToME4 把它做成**独立的一层**，与元素抗性串行叠加，规则变复杂。我们优先把元素抗性做对 |
| 死亡门槛 `die_at` 为绝对值 | ToME4 默认死于 `life <= 0`，没有"流血致死百分比"。**负的 `die_at`** 才是"低于 0 血继续战斗"的机制（Heroism 类）。这个概念挺好，但需要先有死亡/复活流程才谈得上 |

## 5. 落地优先级建议

按"改动量 ÷ 体验收益"排：

| 优先级 | 事项 | 改动量 | 理由 |
|---|---|---|---|
| **P0** | 状态施加的判定夹在 `[5, 95]` | 小 | 一行的事，直接消灭"绝对免疫"与"绝对无效"两个极端 |
| **P0** | 状态合并策略字段（平均 / 取最强） | 小 | 不做的话 DoT 会指数增长；做成字段就永久解决 |
| **P1** | 状态的两层模型（豁免骰 + 时长缩放） | 中 | 数值差距变成"概率 × 时长"两维，层次感提升最大 |
| **P1** | 抗性的乘算合并 + 上限加算 + 穿透只削正抗性 | 中 | 抗性系统的正确性基础，先做对比后做数值 |
| **P1** | `TimeScale` 的加速/减速不对称 | 小 | 防止减速把速度变成 0；顺手 |
| **P2** | 冷却与速度分离 | 中 | 需要先有"回合"概念，避免 haste 指数收益 |
| **P2** | 护甲的 `hardiness` 分割 | 中 | 护甲设计的地基；但要有护甲系统才谈得上 |
| **P2** | 反向资源（均衡类）+ 击杀回复资源 | 中 | 玩法分化最大，但需要角色/职业系统配合 |
| **P3** | 跨档副状态（保底收益） | 中 | 有趣，但要在主判定稳定之后 |

## 6. 已落地的部分

| 原语 | 位置 | 状态 |
|---|---|---|
| `Scale`（`Power` / `Log` / `Limit` + 双锚点） | `behaviors::value::curve` | ✅ 已落地 + 单测 |
| `Rescale`（分段线性压缩，`interval` 可配） | `behaviors::value::curve` | ✅ 已落地 + 单测 |
| RON 侧 `Scale(...)` / `AnchorsRon` / `CurveRon` | `behaviors::content::{descriptor, loader}` | ✅ 已落地 + 端到端测试 |

**测试守住的行为**（这些是契约，不是实现细节）：

- 锚点精确：`x = anchor_low` ⇒ `low`，`x = anchor_high` ⇒ `high`。
- `power < 1` 前期快、`power > 1` 后期快（形状，不是具体数值）。
- `Limit` **永不越过上限**，且单调。
- 非单调的 `Limit` 参数被**拒绝**（返回 `None`）。
- `Rescale` 复现 ToME4 的换段点；第一段之前是恒等；单调且凹；**永不放大利**。
- 曲线是纯函数（同样输入永远同样输出）——战斗可复现的前提。

**测试数量**：`curve_tests.rs` 15 条（曲线 + 压缩），
外加 `loader/tests.rs` 里一条端到端（`.ron` → 解析 → 求值）。
