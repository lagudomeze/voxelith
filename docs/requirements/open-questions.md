# 待澄清问题

读原始讨论时，**答不上来的**都登记在这里，一条一个 ID。禁止在文档里写"视情况而定"——那是没登记的问题。

状态取值：`开放`（等用户回答）/ `已答`（结论已写回 [requirements.md](requirements.md)）/ `转需求`（其实不用问，直接写成了需求条目）。

## 条目格式

```markdown
### Q-001 <一句话问题>
- 状态：开放
- 问题：<具体问什么；给出候选选项比开放式提问更好回答>
- 为什么重要：<它挡住哪条需求或哪个设计决定>
- 影响面：需求 / 设计
```

## 问题清单

### Q-001 引擎选型：Bevy 还是 Godot？
- 状态：开放
- 问题：最终用 Bevy（全 Rust）还是 Godot（Rust/GDExtension 或 GDScript）实现？两条线是并行评估后二选一，还是各自都可能成立？
- 为什么重要：决定 [design/](../design/README.md) 下哪条线是主线，也决定后续分解出的子部分形态。
- 影响面：设计（并间接影响需求中对性能、迭代速度、平台目标的取舍）
- 备注：原始讨论收录后判定是否可关闭。若讨论已给出结论，本条改为 `已答` 并把结论写进 `requirements.md`。
