# 内容与数据

细则层。编号 `CT-xx`。

| ID | 要什么 | 判定标准 | 来源 |
| --- | --- | --- | --- |
| CT-01 | 会随游戏内容增长的集合都放数据文件：技能、状态、怪物、资源、特性、世界参数 | 新增这些内容只改数据文件即可生效 | layers §9 |
| CT-02 | 判断一个集合属于内容还是引擎，判据是"它带不带规则" | 带引擎规则的固定在代码里；只用于比较相等性的名字走数据 | layers §9 |
| CT-03 | 内容分类存放：词汇表（资源、属性、状态、特性的名字与默认值）、技能、状态、玩家、怪物、世界 | 六类内容齐备时游戏可完整启动 | combat-design §8 |
| CT-04 | 内容就绪必须发生在游戏逻辑启动之前 | 内容没准备好时不会出现一个空战场 | combat-design §8 |
| CT-05 | 内容出错必须报出来，并指出是哪个文件；不许静默跑 | 写错一份内容文件时启动报错并指出文件 | combat-design §8 |
| CT-06 | 内容里的引用错误（引用了不存在的资源 / 属性 / 状态）在加载期就能被发现 | 逐项构造错误内容，各自报出对应错误 | combat-design §8 |
| CT-07 | 内容可以热重载：同一标识原地更新，插入一条不影响其它内容的身份 | 往文件中间插一条技能后，其余标识与含义不变 | combat-design §8.2 |
| CT-08 | 热重载出错只报错并保留旧内容，不中断游戏 | 写入语法错的内容文件后，游戏继续跑且用旧内容 | combat-design §8.2 |
| CT-09 | 热重载不重新生成角色、也不重建地形 | 重载后角色与地形网格都不增加 | combat-design §8.2 |
| CT-10 | 只有引擎能力需要改代码（新阵营、新对抗方式、新效果原语），这是可接受的 | 加内容不改代码；加引擎能力要改代码 | combat-design §11 |
| CT-11 | 素材许可干净（CC0、无需署名）；AI 出图只用于方块贴图，不用于逐帧动画 | 素材清单里每一项都是 CC0 | TODO.md:961、1355 |
