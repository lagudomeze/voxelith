# 需求清单

**这里只回答"要什么"。** 怎么做（数据结构、字段清单、判定入口、消息与顺序、加载与存档的实现手段）属于设计，等设计阶段再写。

**分界线**：把实现整个换掉，这条还成立吗？成立 → 需求；只在当前实现下才有意义 → 设计。

**来源**：从重构前项目 `legacy`（提交 `973ddd5`）的文档与工作日志提炼，逐条带出处。

**数字口径**：清单里的具体数字与尺寸都是**当前取值**，可在数值阶段调整；需求本身是其中的机制与关系。

**格式**：编号只增不改；被推翻的移到[第八节](#八明确不做)并注明日期。本清单在 2026-10-09 做过一次级别重排（把实现细节请了出去）。
