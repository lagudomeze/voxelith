## 为什么会有这张表

旧项目的问题表腐烂过：底部写着"已解决"，顶部的"阻塞编码"还挂着（原话留在 `legacy` 的 `docs/OPEN-QUESTIONS.md`）。结论有两条：

1. **别在仓库里维护"未解决的问题"清单**，只维护"已定的事实"清单——定下来的进本表，没定的留在对话里。
2. 被推翻的决定不删除，改本行的结论并注明日期，这样"当时为什么这么定"永远查得到。

## 已定、但属于设计层的机制（2026-10-09）

这些是敲定需求时连带定下的**实现层规则**。它们不进[需求清单](requirements/requirements.md)（需求只回答"要什么"），记在这里供设计阶段取用，也免得同一个问题被重新讨论一遍。

| 规则 | 说明 |
| --- | --- |
| 移动与技能共用一个动作槽、互斥 | 移动本身没有前摇 / 释放点 / 后摇 |
| 槽的交接不对称 | 施法中发起移动 → 立即切换（技能中止）；移动中发起技能 → 当前这一格走完再切换 |
| "可移动施法"是修饰符开关 | 由被动 / 姿态 / 增益提供，默认关闭；它放开的正是上面那条互斥 |
| 技能时间轴的载体分离 | 前摇 = 动作实体；释放点之后动作实体销毁；后摇 = 独立的冷却记录 |
| 打断 / 取消的作用对象只有三类 | 动作实体（只存在于前摇）、冷却记录、决策槽；移动不是合法目标 |
| 阻挡的两类与判定时机 | 占位阻挡 / 地形阻挡；判定发生在每步开始（取出下一格时） |
| 挡住即停的实现 | 不发起这一步、清空路径与移动意图；槽随之空出；不自动重算 |
| 同帧争格的裁决必须确定 | 否则违反"同一份输入必然同一个结果" |
| 相位判据必须包含"未完成的移动" | 否则玩家一开始走，判据仍认为他空闲，时间被冻结、那一格永远走不完 |

## 已否决的旧做法（别再讨论）

旧机制被换掉、或参考实现的做法被判定为坑。记下来是为了**不要重新讨论一遍**。

| 否决的 | 换成了什么 / 为什么不抄 | 来源 |
| --- | --- | --- |
| 独立的生命类型 + "血量归零事件" | 生命不再特殊：血量只是资源之一，"哪个资源是命"是内容语义 | OPEN-QUESTIONS Q18、Q1、Q3 |
| 四阶段伤害管线 | 换成一次对抗包住：原方案要靠注册顺序排规则，组合爆炸 | combat-design §13 |
| 独立抵抗组件 + 数值减伤 | 抵抗改成对抗里的防守方取值，减伤变成可配置的 | combat-design §13 |
| 独立判定层 | 随机收进对抗原语，全游戏只剩一个随机点，战斗才可复现 | combat-design §13 |
| 属性账本 / 显式字段属性表 | 改成键控属性：加一条属性不改代码（代价是丢掉编译期的穷尽检查） | combat-design §13 |
| 阵营与种族混在同一个标签里 | 拆成三个互不干扰的维度 | combat-design §13 |
| 超线性伤害放大 | 参考实现用它补偿被压扁的力量值；别把力量压那么狠就不需要 | numbers §4.8 |
| 死参数 | 参数要么生效、要么不存在（参考实现有传了却从不生效的参数） | numbers §4.8 |
| 照抄参考实现的经验曲线 | 它的衰减分支判错对象，出现过单级 6 倍跳变——是 bug 不是设计 | numbers §4.8 |
| 搬参考实现的代码 | 只取机制与数值设计；它不是依赖、不参与构建 | numbers 开头 |
